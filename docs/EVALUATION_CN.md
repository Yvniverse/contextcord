维护者报告：在 60 个真实 DeepSWE / CCBench 工程任务的同模型、同预算跨会话实验中，官方验证器任务通过数由 **33/60 提升至 43/60**。下表采用维护者提供的汇总结果；正式运行清单、逐任务结果和执行身份正在等待关联。JSON 明确列出这些待补字段。

| 通过率的 95% Wilson 区间 | 42.5%–66.9% | 59.2%–81.5% | 各组比例区间 |

Adaptive Router 的独立对照报告约 23% 未缓存输入 Token 降幅、18% 推理延迟降幅，任务成功率的绝对变化控制在 2 个百分点以内；该对照的任务分母及精确计数待接入运行清单。

## 协议与任务分母

报告中的正式工程任务分母是 **60**，比较的每个条件均为 **60**。会话数、验证器重试数、工程决策数和对抗案例数不作为工程任务分母。300 个独立标注决策与 300 个对抗案例属于另外两项报告评测。

维护者说明正式实验采用预注册、跨会话、同模型、同预算和官方验证器。任务 ID、源码版本、benchmark 构成、模型与思考强度、精确预算、会话截断点、执行顺序、排除规则及预注册快照将与原始运行产物一起关联。

仓库四组接续协议的消融定义如下：

| 组 | 交付给下一会话的上下文 |
|---|---|
| A — A_COLD_START | 无交接 packet 的冷启动接续 |
| B — B_TEXT_HANDOFF | 从共享会话前缀生成自由文本交接 |
| C — C_STRUCTURED_CORE | 结构化工程接续与确定性上下文选择 |
| D — D_STRUCTURED_JEV | 结构化接续与 Jev 类型化上下文选择 |

本次提供的 60 任务汇总包含基线与完整 ContextCord 两个条件。基线对应哪一组、A/B/C/D 各自计数尚未提供，JSON 保留 null。此表是协议定义，并不表示四组均已完成各 60 任务的评测。

## 精确计数、失败与置信区间

基线：**33 个通过 + 27 个失败 = 60**。完整 ContextCord：**43 个通过 + 17 个失败 = 60**。逐任务失败 ID、失败类别、基础设施无效数和排除记录等待正式结果表关联。

通过率与决策准确率采用双侧 95% Wilson score 区间，z = 1.959963984540054。门禁绕过采用双侧 95% Clopper–Pearson 精确区间：本有限测试集观察到 0/300，区间约为 0–1.22%。

配对提升的置信区间需要逐任务配对结果或配对不一致计数；仅凭 33 和 43 无法恢复。探索、Token 和时间降幅的区间需要对应原始观察值。

## 指标定义

- **任务通过率**：通过官方验证器的任务数 / 声明的任务分母。
- **绝对提升**：(43/60 − 33/60) × 100 = 16.6667 个百分点。
- **相对提升**：(43/33 − 1) × 100 = 30.3030%。
- **重复探索**：跨会话重复导航、搜索或读取源码；具体事件标识与聚合方法由运行协议定义。
- **未缓存输入 Token**：provider 输入 Token 减去缓存输入 Token。
- **首次正确修改通过验证器时间**：从声明的接续起点，到正确修改首次通过官方验证器的耗时；按协议规定的样本汇总中位数。
- **类型化决策准确率**：正确的独立标注决策数 / 全部标注决策数。
- **门禁绕过率**：观察到越过既定门禁的未授权行为数 / 对抗案例数。
- **推理延迟**：Router 协议规定时间边界内的模型推理耗时。

降幅统一按 100 × (1 − 实验条件 / 基线条件) 计算，聚合或配对方式以正式协议为准。
